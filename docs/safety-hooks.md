# Safety hooks

Installed by default for every client that supports hooks (use `--no-hooks` to skip). They protect against the common mistakes of agent-driven work, with no stack assumptions built in:

- block reading or editing files that hold secrets, and writing secrets into files or prompts (opaque session ids and directory paths are not secrets; neither is anything inside `.claude`, `.copilot`, `.light-kit` or `specs`)
- block dangerous commands (mass deletion, force push, hard reset, piping downloads into a shell, environment dumps, destructive database statements)
- keep commit messages and pull request text clean: no AI attribution (`Co-Authored-By` an assistant, "Generated with …") and no trailers
- protect version-control internals, the hooks themselves and paths you declare generated or locked
- warn when work starts without an active request or an implement instruction arrives with no written plan, run your format/lint commands after edits, flag secrets in tool output, remind the agent at session start that a user-reported defect or a failed check is a rule trigger too (not only a review finding), without reading the prompt so it works in every language, report each step's token usage and time spent, count each request's agent and skill calls in `.light-kit/agent-skill-usage.md` (with the machine-readable `.light-kit/agent-skill-usage.json` beside it), keep one row per tool call in a single log (`specs/tool-log.md` before a request folder exists, moved into the request's `specs/<NNN-slug>/tool-log.md` when it is created) and commit the remaining log when the agent stops, and give each session its context
- optional: verify before the agent finishes, and an audit log

What is specific to your project (secret file names, secret variable naming, generated paths, format/lint/test commands) lives in `.light-kit/hooks.config.json`, which `light-init` fills from what it finds in your repo. Hook settings stack per level: user, then workspace, then project. With a user-level install in a project that has not run `light-init`, the path rules still apply: paths are resolved from the project's repository root (or the session's folder) rather than the edited file's folder.

The `agent-skill-usage` hook counts calls made through the client's agent and skill tools, attributed to the request the call names (else `(no request)`); a skill applied by reading its file is not an invocation and is not counted. For a use that never becomes a tool call — a skill applied by reading its file, or an agent role performed by the session itself — the agent runs the installed `record-usage.mjs` (`node .light-kit/hooks/record-usage.mjs <agent|skill> <name>`, or `~/.light-kit/hooks/` with a user-level install), which updates the same two files; it takes `--request <slug>` to force the request and `--id <call-id>` to skip a call already counted. Calls made before the hook was installed are not counted by the hook: in the kit repository, `npm run backfill-usage` imports them from the Claude Code session records, attributes each call the same way, skips what is already recorded, and is safe to run again.

See `kit/hooks/README.md` for every hook and key. Hooks need Node 18+ on the machine running the AI client.
