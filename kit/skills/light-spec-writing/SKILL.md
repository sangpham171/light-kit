# Spec writing

- State the **problem and outcome** before the solution.
- Requirements are numbered and testable ("The system shall…"). One idea each.
- Acceptance criteria use Given / When / Then, or a concrete command and its expected result.
- Separate **in scope** from **out of scope**.
- Plans are checklists of small tasks, each with files touched and a verification step. Order them so the project works after every task.
- Keep it high-level: no language- or framework-specific detail unless the project profile requires it.
