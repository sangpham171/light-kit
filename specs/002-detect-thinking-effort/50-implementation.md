## Technical debt
- TD-1 `kit/hooks/lib/effort.mjs` — every source is a client-internal format (transcript field, VS Code state key, Codex config key) with no version check — readers return `''` when it changes, so the failure mode is a silent `unknown`, not a wrong value — status: deferred (inherent to the sources; tests pin the current formats).
- TD-2 `kit/hooks/lib/effort.mjs` — the VS Code state database needs the `sqlite3` binary (Node 22's `node:sqlite` would remove it, but the kit supports Node 18) — status: deferred (fallback is `unknown`).
- TD-3 `kit/hooks/checks/session-context.mjs` — the effort is read at session start only, so a mid-session `/effort` change is not refreshed — status: deferred (change it to read on the prompt event if sessions turn out to change it often).

## Decisions and deviations
- One shared reader module, no new check: `session-context` already runs at session start and its output reaches the agent.
- Client-specific sources, never cross-client: a Claude Code session never reads VS Code's setting and vice versa.
- Copilot: the hook payload does not distinguish VS Code from the Copilot CLI, so a CLI session on a machine with VS Code reports VS Code's setting. Accepted and stated in `docs/usage.md`; without it detection would be lost for VS Code too.
- Cursor is attempted through the same VS Code key; if its database does not carry it, the result is `unknown` (as before).
- Detection runs only when the project is enabled (the existing early return for a user-level install without `.light-kit/`).
